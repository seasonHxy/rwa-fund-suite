# 威胁模型与安全边界

## 已覆盖的风险

- 未授权登记、规则修改、铸造、销毁、冻结、NAV 更新和订单处理。
- 未验证、身份过期、禁用国家、阻断钱包和超持仓上限的转账。
- 申购/赎回重复处理、非订单所有者取消、NAV 变化造成的滑点。
- ERC-20 外部调用失败与重入。
- DvP 签名伪造、错误买方、过期、nonce 重放、跨链/跨合约重放和高 `s` 签名。
- 余额、总供应、冻结额和身份合规的状态型不变量。

## 自审计发现与修复

初版基金把所有合约支付币余额都视为赎回流动性，因此经理可能先用“尚未处理且仍可取消的申购资金”兑付赎回，导致后续取消申购失败。修复方式是单独记录 `pendingSubscriptionAssets`，赎回只能使用扣除该储备后的余额，并加入回归测试。

这类问题不是重入或整数溢出，而是资产负债隔离失败，正是 RWA/DeFi 审计应优先建立的资产流不变量。

## 已知限制

- 自制 `RoleControl` 与 `SafeTransferLib` 只为离线教学；生产版应迁移到固定版本且经过审计的库。
- 身份登记只是链上简化记录，没有 ONCHAINID、Claim Topics、Trusted Issuers 或隐私设计。
- 合规引擎没有完整的模块生命周期、供应限制、转账频率、锁仓期和批量操作。
- NAV 由单一角色直接写入，没有签名聚合、数据新鲜度、偏差阈值和应急流程。
- 没有费用、份额精度策略、会计日、cut-off、队列批次、现金缓冲与真实托管对账。
- 合约不可升级；也未覆盖 timelock、多签、部署验证、监控和事故响应。
- DvP 只处理两个 ERC-20-like token，不处理部分成交、批量净额或法币链下最终性。

## 生产化门槛

1. 用正式标准实现和 OpenZeppelin 5.x 组件替代教学基础设施。
2. 完成权限矩阵、管理员轮换、密钥丢失和紧急暂停演练。
3. 加入 fork、差分、静态分析、覆盖率门槛与独立第三方审计。
4. 对法律载体、持有人名册、NAV 来源、托管银行和链上状态建立可审计对账。
5. 若采用升级代理，必须增加初始化锁、升级授权和存储布局回归测试。
